# 00. Principles and Scope

## Purpose

This compendium defines how a small or medium software organization (1 to 15 engineers, one to a few production systems) builds, reviews, ships, and operates software when AI assistance is part of everyday work. It is deliberately not a heavyweight process: every practice has a **minimum form** a team can adopt in an afternoon and a **scale-up note** for later.

## How to Read the Guides

- **MUST** is a rule. Breaking it needs a written exception in the PR or an ADR.
- **SHOULD** is the default. Deviate when you have a reason and can state it.
- **Minimum form** is the smallest version of the practice that still counts as doing it.
- **Scale-up** says what to add as the team or risk grows. It is not required today.
- **AI note** says what changes when the author or reviewer is an AI agent.

## Principles

1. **Main is always releasable.** Nothing reaches `main` except through a reviewed pull request that passed the gates.
2. **Every change has a reason.** It traces to an issue, or states in the PR why none exists.
3. **Automate the boring checks, spend human attention on judgment.** Linting, typing, tests, and scanning run in CI. Reviewers look at design, risk, and intent.
4. **Data is the critical asset.** Anything that can lose or corrupt user data gets a snapshot, a rollback, and a second pair of eyes.
5. **Decisions are written down.** Costly-to-reverse choices get an ADR; everything else lives in the PR.
6. **One source of truth.** A fact (version, count, command, policy) lives in one place and is referenced, not copied.
7. **Claims need evidence.** A badge, a test count, or a "works well" must be generated by a tool or backed by a measurement, or it is left out.
8. **AI output is code like any other.** It meets the same gates, review, and Definition of Done as human work. Authorship never lowers the bar.
9. **Right-size the process.** If a rule costs more than the risk it removes, simplify it and record why.

## Profiles

Each repository declares two switches in `.agents/rules/project.md`:

- `team-profile: solo | team`, decided by headcount.
- `ships-to-users: yes | no`. Guides 11 to 14 (release, deployment, data safety, operations) apply when `yes`. A local tool or a research repo says `no`.

| | Solo (one engineer) | Team (two or more) |
|---|---|---|
| Review | The sole engineer is author and final reviewer; the AI review is the second pair of eyes | One human approval from someone other than the author |
| Definition of Done | Five items (guide 05) | Nine items (guide 05) |
| Cooling-off | 24 hours only for destructive migrations and data deletions | Not needed; the second reviewer covers it |
| Branch protection | Require a PR and CI checks, **zero** required approvals | Require a PR, CI checks, and one approval |
| Roles | One named owner | Roles per guide 16 |
| Incidents | Stabilize, roll back, write a five-line note | Severities and blameless review (guide 14) |
| Backlog review | Quarterly | Monthly |
| Coverage | Reported by CI | Ratchet |
| Issue templates | Optional | Required |

A repo moves from `solo` to `team` when a second engineer joins. Independently of the profile, a repo that handles personal or financial data applies guides 08 and 13 in full. Everything not listed above follows the guides as written.

## Scope

In scope: source control, commits, pull requests, issues, review, testing, CI, dependencies and security, architecture decisions, documentation, versioning, release, deployment, data safety, operations, AI-assisted development, and roles.

Out of scope: product management, hiring, and tool selection beyond the minimum (Git hosting, a CI service, an issue tracker).

## Language Policy

- **English** for everything stored in a repository: documents, comments, branch names, module and file names, commit messages, PR descriptions, issue titles.
- **Portuguese (Brazil)** is allowed only in chat between people and assistants.
- Legacy documents in another language are either migrated when next edited or marked `legacy` at the top. They are not silently left as-is.

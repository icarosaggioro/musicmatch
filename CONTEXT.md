# MusicMatch

MusicMatch is an AI-native local music management, curation, and DSP playback system designed for high-performance indexing of large-scale audio libraries on Windows.

## Language

### Audio & Library Domain

**Track**:
A single recorded musical piece backed by an audio file (e.g., MP3) with associated acoustic and semantic metadata.
_Avoid_: Song, audio item, music file

**Library**:
The persistent catalog of all scanned tracks, playlists, and acoustic indices managed by the application on local storage. It is explicitly decoupled from any single directory or drive root, allowing tracks to be stored anywhere across multiple disks.
_Avoid_: Collection, database, audio folder, root folder

**Acoustic Fingerprint**:
A compact numerical vector representing the perceptual audio signature of a track used for acoustic identification and deduplication. In MusicMatch it is a sequence of 32-bit sub-fingerprints (~11 per second, first 120 s of audio, algorithm `mmfp1`) compared by bit error rate (ADR 0014).
_Avoid_: Audio hash, sound ID

**Acoustic Analysis**:
The incremental, resumable `/analyze` pass that decodes each track once to measure its Loudness Measurement, tempo, Musical Key, Acoustic Fingerprint and Waveform Summary. It is deliberately separate from scanning, which only reads tags and file stats.
_Avoid_: Deep scan, DSP scan, re-index

**Analysis Stamp**:
The file modification time, size and analysis version recorded with a track's analysis. When the stamp no longer matches the catalog (the file changed) or the version is outdated, the track is pending analysis again.
_Avoid_: Analysis cache key, checksum

**Musical Key / Camelot Code**:
The detected tonic and mode of a track (e.g. `A minor`) and its position on the Camelot wheel (e.g. `8A`) used for harmonic mixing; adjacent codes mix smoothly.
_Avoid_: Tone, scale, pitch

**Exact Acoustic Duplicate**:
Two or more tracks whose Acoustic Fingerprints are bit-identical with compatible durations: the same decoded audio, regardless of tags, file names or container.
_Avoid_: Same file, copy, hash duplicate

**Fuzzy Acoustic Match**:
Two or more tracks whose Acoustic Fingerprints differ by at most 20% of their bits at the best alignment: the same recording across re-encodes, bitrates, sample rates or re-rips.
_Avoid_: Similar song, fuzzy match (which names the tag-based Fast Relocation heuristic), cover detection

**Waveform Summary**:
A lightweight condensed array of peak and RMS amplitude values used for instant UI visual rendering.
_Avoid_: Sound curve, audio graph

**Loudness Measurement**:
Integrated perceptual audio loudness calculated in LUFS according to the EBU R128 standard for volume normalization.
_Avoid_: Volume level, gain factor

**Canonical Path Hash**:
The deterministic unique identifier (`id`) generated by computing the full SHA-256 hash (64 hex characters) of the lowercase, normalized POSIX path string of the audio file, prefixed with `trk_`.
_Avoid_: Random ID, UUID, short hash, raw path as key

**Stat-Cache**:
The high-speed filesystem caching mechanism comparing modification timestamp (`mtime`) and file size (`size_bytes`) to bypass redundant disk I/O and DSP analysis during scanning.
_Avoid_: Fast check, timestamp scan

**Track Availability**:
The operational accessibility status of a track's backing audio file on local storage (`AVAILABLE` vs. `MISSING`).
_Avoid_: File existence, dead track

**Soft Delete / Missing State**:
The non-destructive lifecycle state applied to a track when its backing audio file is unreachable on disk, preserving metadata, playlists, and acoustic indices.
_Avoid_: Hidden track, ghost track, silent deletion

**Manual Purge / Prune**:
An explicit, two-stage administrative operation requiring the confirmation passphrase `PLEASEPRETTYPLEASE` to permanently purge missing tracks from the database.
_Avoid_: Auto-clean, silent wipe, one-click delete

**Auditor Subagent (Library Healer)**:
An opportunistic, lightweight background agent spawned when an unavailable track is detected at runtime, investigating parent folder moves, drive disconnections, and reconciling track states without freezing the UI.
_Avoid_: Background scanner, watcher thread, fixer bot

**Fast Relocation Match**:
The deterministic reconciliation heuristic that identifies moved or renamed audio files by matching exact file size in bytes, duration, title, and artist against currently missing tracks, migrating database keys and preserving acoustic analysis without re-running DSP.
_Avoid_: Re-import, fuzzy match, duplicate track

**Play Queue**:
The persistent, ordered list of entries the player goes through; the same track may appear several times. Played entries stay until the user removes them; a cursor marks the entry that plays next. `/queue-add` inserts at the cursor (plays next); `/queue-add-last` appends. Every command operating on it is named `/queue-<action>`.
_Avoid_: Playlist (a named, curated collection), backlog, up-next list

**Queue Pass**:
One run through the Play Queue from the entry at the cursor to the last entry. Entries before the cursor have been passed in the current pass (✓ in `/queue`). A pass ends by stopping, or, with Repeat Mode on, by wrapping to the first entry and starting a new pass.
_Avoid_: Loop, cycle, round

**Repeat Mode**:
The persistent queue setting (`/queue-repeat`) that starts a new Queue Pass from the first entry when the last one ends, instead of stopping. It repeats the entire queue, never a single track. Excludes Consume Mode.
_Avoid_: Loop mode, repeat-one, continuous play

**Consume Mode**:
The persistent queue setting (`/queue-consume`) under which a queue entry leaves the Play Queue once it has been played (the Play Count rule) and playback moves on from it (it ends, `/next`, `/play <id>`). Entries skipped early, stopped, paused or unavailable stay. Off by default: played entries are kept. Excludes Repeat Mode.
_Avoid_: Auto-remove, auto-clean, pop mode, history trimming

**Queue Reorder**:
Shuffling (`/queue-shuffle`) or sorting (`/queue-sort`) the whole Play Queue, also during playback. It rearranges the list itself, so `/queue` always shows the real play order. Playback continues from the current entry: sorting keeps it at its new position, shuffling moves it to the top.
_Avoid_: Shuffle mode, sort mode, play order, random play

**Playlist**:
A named, ordered list of Library tracks kept in the catalog; the same track may appear several times. It is filled from the Play Queue (`/playlist-save`) and loaded back into it (`/playlist-load`), and exchanged with other players as M3U/M3U8. Its entries follow moved tracks, keep missing (soft-deleted) ones, and leave when a track is removed from the Library. Names are unique ignoring case and accents. Every command operating on it is named `/playlist-<action>`; `delete` removes the playlist itself, `remove` takes tracks out of it (by ID: every occurrence; by `#position`: one entry), as `/queue-remove` does for the queue.
_Avoid_: Queue (the transient list the player goes through), collection, mix, album

**Now Playing**:
The single track currently loaded in the player, whether playing or paused. It is not part of the Play Queue.
_Avoid_: Current song, active file

**Resume Point**:
The persisted paused track together with its playback position and the time already listened; created by `/pause` or by leaving the application while a track plays, and continued by `/pause` or `/play`. `/stop` discards it and returns to the first queue entry.
_Avoid_: Bookmark, last song, saved state

**Play Count**:
The number of times a track was actually listened to past the play-count threshold (60 seconds of listening, or the whole track when shorter); each counted play also increments the library-wide Total Play Count and appends a Play History entry.
_Avoid_: Views, hits, queue count

**Play History**:
The append-only log of counted plays (track, timestamp, listened seconds) kept even when a track is later unindexed; raw material for learning listening preferences.
_Avoid_: Scrobble log, recently played list

**Short Track ID**:
Any unique prefix (at least 4 hex digits, `trk_` optional) of a Canonical Path Hash ID accepted by playback commands; listings show the first 8 hex digits (e.g. `trk_3fa2b9c1`).
_Avoid_: Track number, index, alias

### Diagnostics Domain

**Issue**:
A foreseen problem with a resource (file, folder, track, playlist, playlist file) or the environment (audio device, database) met while MusicMatch worked, kept in the catalog for the user to review. One Issue per kind and subject: meeting it again counts an occurrence. Reported by services through a non-blocking, thread-safe reporter; listed with `/issue`.
_Avoid_: Error queue (the Play Queue is the only queue), error, bug, alert, log entry

**Dismiss / Delete (an Issue)**:
Dismiss keeps the Issue as silenced: it is never raised again, however often it recurs, until purged for not recurring (180 days). Delete forgets it: the same problem is registered as a new Issue if it happens again.
_Avoid_: Ignore, clear, resolve (reserved for automatic resolution, ADR 0020)

**Developer Log**:
The rotating text file (`data/logs/musicmatch.log`) where unforeseen failures (bugs) from any thread are written with their traceback; the screen shows only a one-line notice with a reference to the entry. Foreseen problems are Issues, not log entries.
_Avoid_: Error log (ambiguous), console log, debug output

### Ingestion & Acquisition Domain

**Staging Area**:
A designated temporary directory partitioned by isolated download sessions where freshly acquired audio streams and initial tags reside before validation or library promotion.
_Avoid_: Cache, temp folder, dump

**Download Session**:
A uniquely scoped, timestamped subfolder within the staging area dedicated to a single user acquisition request, isolating incoming files from concurrent or prior operations.
_Avoid_: Batch run, download job

**Managed Library Directory**:
An officially designated canonical root directory where audio tracks are promoted, structured into standardized subfolders (e.g., Artist/Album), and maintained under strict system naming conventions, distinct from arbitrary external storage paths.
_Avoid_: Primary folder, base folder, app directory

**Track Promotion**:
The formal workflow step where an audio file in the staging area is inspected, validated against metadata standards, retagged via mediafile, and moved into the managed library directory.
_Avoid_: Copying, importing, file transfer

**Extended Metadata**:
Optional semantic facets (version attributes like Remaster, Live, Acoustic, and Collaborators) extracted during web title sanitization and preserved as queryable attributes in the catalog rather than polluting canonical track titles.
_Avoid_: Extra tags, title remnants, noise

**Search-to-Download**:
The query-driven acquisition workflow enabling users to discover candidate audio tracks via direct YouTube search queries or LLM query expansion before initiating downloads.
_Avoid_: Web scrape, auto-downloader

**Session Resolution**:
The explicit user decision lifecycle for a download session, requiring tracks to either be individually promoted to the Managed Library or discarded as a whole.
_Avoid_: Auto-expire, session timeout

**Promotion Collision**:
An invariant condition where a staged track targeted for promotion matches an existing file or canonical ID in the Managed Library, blocking the transfer and preserving the staged copy for manual inspection.
_Avoid_: Overwrite, silent skip

**AI-Assisted Search (`--ai-assist`)**:
An explicit acquisition query mode that routes ambiguous, lyrical, or descriptive inputs through the LLM for canonical artist and title deduction prior to querying web audio indexes.
_Avoid_: Smart download, magic search

**Session Manifest**:
An isolated, self-contained `session.json` file stored within each download session directory that records creation timestamp, source query or URL, acquisition status, and tracked file metadata.
_Avoid_: Session database, state log

**Atomic Cancellation**:
A resilience guarantee ensuring that an interrupted download operation (via `Ctrl+C` or network failure) immediately purges partial artifacts (`.part`, `.ytdl`), leaving the staging area free of corrupted files.
_Avoid_: Broken resume, orphaned temp

**Managed Library Taxonomy**:
The canonical on-disk directory hierarchy within the Managed Library partitioned into three strict top-level namespaces:
1. `Artists/<Artist>/<Album>/` (with `Artists/<Artist>/Singles/` for standalone tracks)
2. `Various Artists/<Album>/` for multi-artist commercial releases and soundtracks
3. `Collections/<Collection_Name>/` for custom user-curated compilations kept physically unified
_Avoid_: Flat storage, unpartitioned root

**Compilation Album**:
An official release containing tracks performed by multiple distinct artists united under a single release title, organized on disk under `Various Artists/<Album>/` to preserve album cohesion.
_Avoid_: Split album, fragmented release

**User Collection**:
A user-defined, thematic compilation of tracks (e.g. Mixtape, Gym Set) preserved physically in a single cohesive directory under `Collections/<Collection_Name>/` regardless of artist diversity.
_Avoid_: User folder, ad-hoc dump

**Managed Library Resolution**:
The deterministic precedence hierarchy used to resolve the Managed Library Directory: `.env` override > dynamic configuration store > cross-platform OS standard music directory (`~/Music/MusicMatch`).
_Avoid_: Hardcoded path, fixed directory

**Write Access Probe**:
An atomic filesystem capability test (creating and immediately deleting a hidden `.musicmatch_probe` file) executed upon path registration to guarantee read/write permissions before accepting a directory.
_Avoid_: Permission check, read-only assumption

**Critical Path Guard**:
The security boundary blocking system-critical paths (`C:\`, `/`, `/etc`, `C:\Windows`, `C:\Program Files`, or the application source directory) from being designated as library storage.
_Avoid_: Open filesystem, root acceptance

**Storage Disconnection Guard**:
The operational safety policy that halts track promotion and retains staged files safely in the Staging Area whenever the target physical drive or network mount is unreachable.
_Avoid_: Silent failure, fallback dump

### Library Maintenance & Lifecycle Domain

**Unindex**:
The non-destructive removal of a track's metadata record from the database catalog while leaving the backing audio file on disk completely untouched.
_Avoid_: Remove track, delete record, wipe

**Physical Delete**:
An administrative operation that moves the backing audio file to the Operating System Trash/Recycle Bin and cascades deletion across all database records and search indices.
_Avoid_: Hard delete, silent unlink, permanent wipe

**Double Confirmation Protocol**:
An explicit safety barrier requiring interactive confirmation before executing bulk physical deletions or irreversible batch modifications across multiple tracks.
_Avoid_: Auto-confirm, single-click delete, silent purge

**Library Import**:
The formal ingestion of external audio directories into the canonical Managed Library Directory, reorganizing files into the standard taxonomy via copy or move modes.
_Avoid_: Bulk scan, file transfer, library merge

**Source Deletion Pre-Flight Check**:
An atomic permission verification on source audio files and parent directories prior to executing move-based imports, ensuring complete transfer without orphaned files.
_Avoid_: Safe move, move check, write test

**Library Reorganization**:
The physical realignment and renaming of audio files within the Managed Library Directory to reflect newly updated artist or album metadata.
_Avoid_: File sorting, folder cleanup, disk rename

**Track Retagging**:
The operation of writing updated metadata tags directly into an audio file on disk via mediafile while atomically updating the database catalog and FTS5 index.
_Avoid_: Tag editing, tag patch, rename

**Send-to-Trash Deletion**:
The safe file elimination mechanism routing physical audio files to the host Operating System Recycle Bin rather than unrecoverable filesystem unlinking.
_Avoid_: Hard delete, permanent unlink, silent erase

**External Storage Warning**:
A highlighted alert rendered whenever an administrative mutation or deletion targets an audio file residing outside the Managed Library Directory in user personal directories.
_Avoid_: Generic prompt, blind confirm

**Count-Verification Gate**:
The double-confirmation requirement forcing the user to type the exact integer count of affected tracks to unlock batch physical deletions.
_Avoid_: Simple confirm, y/n prompt for batch

**Per-Item Pre-Flight Isolation**:
The non-destructive transfer principle where each individual file's read, write, and source-deletion permissions are validated before relocating it, leaving locked files untouched in their source directory.
_Avoid_: All-or-nothing move, blind transfer

**Audit Dashboard**:
The diagnostic summary view rendered by `/audit` cataloging library health indicators, including duplicates, missing files, untagged tracks, and degraded bitrates.
_Avoid_: Log printout, error dump

### Agent & AI Domain

**Orchestrator**:
The primary coordinating controller that maintains application state, manages user interaction, and delegates domain tasks to specialized agents and tools.
_Avoid_: Main loop, master script, manager

**Subagent**:
An autonomous, specialized agent spawned by the orchestrator with scoped permissions and dedicated prompts to solve bounded tasks (e.g., library auditor, metadata curator).
_Avoid_: Worker, background task, bot

**Tool**:
A deterministic, strongly-typed function exposed to agents to perform system actions, run DSP algorithms, or query storage.
_Avoid_: Function, command, plugin

**Integrity Audit**:
The process of identifying corrupted files, missing tags, or upscaled audio transcodes, recorded into an audit log for remediation.
_Avoid_: Error check, bug scan

### Harness & Interface Domain

**Harness**:
The interactive runtime environment and event loop that hosts the Orchestrator/Agent, routes administrative slash commands, and manages user session boundaries.
_Avoid_: REPL loop, terminal runner, shell script

**Command**:
A deterministic system/administrative operation (prefixed with '/') executed directly by the harness without invoking the LLM.
_Avoid_: Prompt, query, chat message

**Renderer / View**:
The decoupled presentation layer responsible for formatting observability logs, banners, and diagnostic tables for the user interface.
_Avoid_: Print statement, logger, console output
